Four data structures, each with one job.

Every command maps to a structure from the course. The diagrams show what each one holds.

O(L) per path

Two tries for .minigitignore

Files and folders go into a forward trie. Extension rules such as *.log are stored reversed, so a suffix match becomes a prefix match. Each check costs the length of the path, however many rules exist.

path trie        b-u-i-l-d-/            build/      line 2
                 s-e-c-r-e-t-.-e-n-v    secret.env  line 3
extension trie   g-o-l-.                *.log       line 1

query  logs/app.log  reversed  gol.ppa/sgol  matches line 1
Sparsh Jain: ignore engine, add, remove
O(log n) lookup

An ordered set for the index

Staged paths live in a std::set (a red-black tree): no duplicates, and always sorted, so .minigit/index keeps a stable order.

index = { README.md,
          main.cpp,
          src/lexer.cpp }
Sparsh Jain: staging index
O(1) at both ends

Two deques for undo and redo

A commit pushes the previous state onto the undo deque, and undo moves it across to redo. Past 20 entries, pop_front() drops the oldest.

undo  [ A | B | C ]  push_back
redo  [ ]            cleared by a new commit
Krish Bajaj: commit, undo, redo
O(n) walk, either way

A doubly linked list for log

log follows parent links from HEAD and links every commit both ways, so newest-first and --reverse are one walk from either end.

first <-> second <-> third
                          HEAD
Snehil Joshi: log, log --reverse

One static binary, one command table

Built with -static, so minigit.exe needs nothing beyond Windows itself. Every command is a row in one table that also generates its help and usage.

See the architecture

Five layers, one direction.

A command enters at the top. The dispatcher finds it in the command table and calls one module. Modules return result structs and never print; the CLI turns results into messages and exit codes.

That split is what lets each module be tested on its own: seven test suites run with make test.

  1. CLI and command tableLooks up the command, checks its arguments, prints help, usage and typo suggestions.CLI.cpp
  2. Command modulesinit, add and remove, ignore, commit with undo and redo, log.*Command.cpp
  3. Ignore engineParses .minigitignore into the two tries and reports which line matched.IgnoreManager.cpp, Trie.cpp
  4. Staging and historyThe ordered-set index, the undo and redo deques, and the linked commit log.StagingArea, CommitHistory, CommitLog
  5. Storageobjects/<id>/ metadata and snapshots, HEAD, refs/heads/main, index, history..minigit/

Every command.

Eleven commands, grouped by what they work on. Run any of them in the sandbox above.

Repository

Start tracking a folder.

  • minigit init

    Creates .minigit/ (objects, refs/heads, HEAD, index) and .minigitignore. Safe to re-run.

Staging

Choose what the next commit contains.

  • minigit add <file|dir>

    Stages a file, or every non-ignored file in a folder.

  • minigit add .

    Stages every non-ignored file in the repository.

  • minigit add -v <file>

    Shows whether a file is staged, ignored or missing.

  • minigit remove <file|dir|.>

    Unstages files; your files on disk are never touched. Alias: rm.

Help and install

Find your way around, and put MiniGit on your PATH.

  • minigit help [<command>]

    Lists every command, or the usage of one. minigit <command> --help works too.

  • minigit install

    Copies MiniGit into a folder on your PATH. It also does this on first run.

  • minigit uninstall

    Removes the installed copy.

Ignore rules

Keep build output and secrets out of history.

  • minigit ignore

    Lists the rules in .minigitignore with line numbers.

  • minigit ignore <pattern>

    Adds a file, folder (build/) or extension (*.log) rule.

  • minigit ignore -r <pattern>

    Removes a rule; later line numbers shift up.

  • minigit ignore -v <path>

    Shows whether a path is ignored, and by which line.

History

Record, step back and read your commits.

  • minigit commit "<message>"

    Records the staged files and clears the index. -m "<message>" also works.

  • minigit undo

    Moves HEAD back one commit and restores its staged files. Same as commit undo.

  • minigit redo

    Re-applies the last undone commit. Same as commit redo.

  • minigit log [--reverse]

    Shows history newest first, or oldest first with --reverse.

Wrong or extra arguments print that command's usage and exit with 1. A typo such as minigit comit suggests the closest command.

Three phases, two done.

The plan from the Phase 1 design report, and where each part stands in the code today.

  1. Phase 1, delivered

    Planning and design

    Scope, command set, .minigit/ layout, class responsibilities and the choice of data structures.

  2. Phase 2, implemented

    Repository and commit module

    init, add, ignore, commit and log, plus undo and redo on two deques and a table-driven CLI.

  3. Phase 3, next

    Restore, test and document

    checkout to restore a chosen version and rollback to undo that restore, with validation, error handling and final documentation.

In scope

  • One user, one local repository
  • Text files such as .cpp, .h, .md
  • Linear history on a single branch, main
  • File, folder and extension ignore rules

Out of scope

  • Remotes: push, pull and clone
  • Branches and merging
  • Diffs and delta compression
  • Multiple users or authentication
