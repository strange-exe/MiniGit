Motivation

Why MiniGit? Folder Chaos vs. Version Control

Students frequently struggle with manual copy-paste folder backups. MiniGit abstracts the essential VCS engine into an elegant, observable workflow.

The Problem

Manual Folder Duplication

Saving copies like project_final, project_final_v2, project_final_LATEST leads to confusion, untracked changes, and catastrophic accidental overwrites.

assignment_final/
assignment_final_v2/
assignment_REAL_FINAL/
assignment_LATEST_DO_NOT_DELETE/
  • Inability to track exact file diffs
  • Wasted disk space & duplicate clutter
  • High risk of recovering the wrong snapshot
The MiniGit Solution

Structured Local Version Control

MiniGit isolates the core workflow — track, commit, inspect, restore — into a clean local .minigit/ directory backed by efficient C++ data structures.

my_project/ .minigit initialized
$ minigit init
$ minigit add main.cpp
$ minigit commit -m "Core logic added"
  • Clean linear history graph via Linked List
  • Instant snapshot lookups via Hash Tables
  • Safe state rollback engine using Stack

Command Matrix

Supported Terminal Commands

MiniGit supports six core commands covering complete repository management.

minigit init Repository Setup

Creates a new local repository by building the .minigit/ directory structure, initializing HEAD pointer and empty staging index.

Syntax: ./minigit init
minigit add File Tracking

Selects specified files for tracking. Generates content hash mappings and updates the staging area hash table.

Syntax: ./minigit add <file>
minigit commit Version Snapshot

Saves current version of tracked files with a timestamped message into .minigit/objects/, appending a new node to the history linked list.

Syntax: ./minigit commit -m "message"
minigit log History Inspection

Traverses the Singly Linked List from HEAD back to root commit, displaying commit hashes, timestamps, and messages.

Syntax: ./minigit log
minigit checkout State Restoration

Restores repository files to a previously saved commit snapshot. Pushes pre-restoration working state onto the Rollback Stack.

Syntax: ./minigit checkout <commit-id>
minigit rollback Undo Restoration

Pops the top state snapshot off the Rollback Stack and restores repository files back to the state prior to the last checkout.

Syntax: ./minigit rollback
Development Phases

Project Roadmap

MiniGit follows a disciplined three-phase development lifecycle.

Phase 1 — Completed

Planning & System Design

Defined command scope, folder structure, class relationships, and data structure choices. Finalized flow specs for `init`, `add`, `commit`, `log`, `checkout`, and `rollback`.

Phase 2 — Active Development

Repository & Commit Core

Implementing `init`, `add`, `commit`, and `log` in C++. Building the `.minigit` object storage layer, linked list history graph, and hash table index lookup.

Phase 3 — Upcoming

Restoration, Stack Engine & Verification

Implementing `checkout` and `rollback` backed by stack data structures. Comprehensive edge-case testing, performance benchmarking, project report, and live demo preparation.

System Boundaries

Scope & Assumptions

Focusing strictly on core concepts guarantees stability and educational clarity.

Supported In-Scope Features

  • Single user on a single local filesystem
  • Tracking text-based files (.cpp, .h, .txt)
  • Linear commit history backed by Singly Linked List
  • Local .minigit/ directory metadata storage
  • Non-destructive checkout with stack rollback

Out-of-Scope (Full Git Features)

  • Remote server synchronization (push / pull / remotes)
  • Multi-user collaboration & authentication
  • Automated 3-way merge & conflict resolution
  • Binary delta-compression storage
