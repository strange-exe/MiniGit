Core Capabilities

Why MiniGit? Built for Speed & Transparency

MiniGit combines the simplicity of educational algorithms with production-grade system mechanics.

O(L) Performance

Dual Trie .minigitignore

Unlike traditional string-scanning ignore lists, MiniGit compiles ignore patterns into two specialized prefix trees: a Forward Directory Trie for prefixes (e.g. build/) and a Reversed Suffix Trie for file extensions (e.g. *.log).

  • Sub-millisecond ignore verification without regex overhead
  • Pattern line numbers tracked for instant diagnostic tracing
  • Verify rules with minigit ignore -v <path>
Staging Workspace

The Staging Index (.minigit/index)

MiniGit decouples working directory files from commit snapshots via a dedicated staging index. The index records file paths, modification states, and content blob hashes before commits are permanently sealed.

  • Atomic staging with minigit add <file> or add .
  • Precise staged verification via minigit add -v <file>
  • Instant unstaging with minigit remove <file>
Zero Dependencies

100% Standalone Executable

MiniGit is compiled with static linking (-static -static-libgcc -static-libstdc++) in modern C++. It contains zero external DLL dependencies and runs out-of-the-box on any Windows machine.

  • Portable 2.7 MB binary (`minigit.exe`)
  • Uses native Windows subsystem calls via `ghc::filesystem`
  • Built-in self-installation to `%LOCALAPPDATA%\Microsoft\WindowsApps`
Safe State Restores

Linear History & Rollbacks

Commits are organized into a Singly Linked List tracked by the HEAD pointer. Checking out an older commit safely pushes the current state onto a LIFO Rollback Stack, preventing accidental state loss.

  • Fast chronological history traversal via minigit log
  • Seamless checkout with minigit checkout <hash>
  • One-step undo restoration via minigit rollback
Motivation

Why MiniGit? Folder Chaos vs. Version Control

Students frequently struggle with manual copy-paste folder backups. MiniGit abstracts the essential VCS engine into an elegant, observable workflow.

The Problem

Manual Folder Duplication

Saving copies like project_final, project_final_v2, project_final_LATEST leads to confusion, untracked changes, and catastrophic accidental overwrites.

assignment_final/
assignment_final_v2/
assignment_REAL_FINAL/
assignment_LATEST_DO_NOT_DELETE/
  • Inability to track exact file diffs
  • Wasted disk space & duplicate clutter
  • High risk of recovering the wrong snapshot
The MiniGit Solution

Structured Local Version Control

MiniGit isolates the core workflow — track, commit, inspect, restore — into a clean local .minigit/ directory backed by efficient C++ data structures.

my_project/ .minigit initialized
$ minigit init
$ minigit ignore *.log build/
$ minigit add main.cpp
$ minigit commit -m "Core logic added"
  • Dual Trie ignore filtering for O(L) rule matching
  • Clean linear history graph via Linked List
  • Instant snapshot lookups via Hash Tables
  • Safe state rollback engine using Stack

Command Matrix

Supported Terminal Commands

MiniGit supports comprehensive repository management, pattern ignoring, staging verification, and rollback operations.

minigit init Repository Setup

Creates a new local repository by building .minigit/, objects/, HEAD pointer, empty staging index, and default .minigitignore.

Syntax: minigit init
minigit add Staging Index

Stages files into .minigit/index while honoring .minigitignore. Supports single files or recursive tracking with minigit add ..

Syntax: minigit add <file> | minigit add .
minigit add -v Staging Check

Verifies if a file is currently staged in the index. Returns '<file>' is staged (IS_STAGED) or ignore/untracked status.

Syntax: minigit add -v <file>
minigit remove Unstage Files

Unstages tracked files from the .minigit/index without modifying or deleting the working directory file on disk.

Syntax: minigit remove <file> | minigit remove .
minigit ignore Trie Ignore Engine

Adds patterns to .minigitignore and recompiles the in-memory Dual Trie. Supports wildcards (*.log), folders (build/), and exact files.

Syntax: minigit ignore <pattern>
minigit ignore -v Trie Diagnostic

Tests a path against the Dual Trie prefix tree in O(L) time, reporting exact ignore pattern match and line number in .minigitignore.

Syntax: minigit ignore -v <path>
minigit commit Version Snapshot

Saves all currently staged files into a permanent version snapshot node, writing blobs to .minigit/objects/ and advancing HEAD.

Syntax: minigit commit -m "commit message"
minigit log History Inspection

Traverses the Singly Linked List from HEAD back to the root commit, outputting commit hashes, timestamps, messages, and parent references.

Syntax: minigit log
minigit checkout State Restoration

Restores the workspace to an earlier commit snapshot. Automatically pushes the pre-checkout state onto the LIFO Rollback Stack.

Syntax: minigit checkout <commit-hash>
minigit rollback Undo Restoration

Pops the top state snapshot off the Rollback Stack and restores the repository to the state prior to the last checkout.

Syntax: minigit rollback
minigit install PATH Setup

Copies the binary to %LOCALAPPDATA%\Microsoft\WindowsApps (already in user PATH) so minigit runs from any terminal without .\.

Syntax: minigit install

Development Lifecycle

Project Roadmap

MiniGit follows a disciplined three-phase development lifecycle for PBL in DS CPP. Phase 1 Delivered · Phase 2 Currently in Motion.

Phase 1 — Completed Milestone

Planning, Architecture & Core CLI Implementation

Implemented modular 5-layer pipeline, Dual Trie ignore engine (O(L) path filtering), init, add (with -v staged check), remove, commit, log, checkout, rollback, and zero-dependency standalone compilation.

Phase 2 — Currently in Motion

Hash Delta Storage, Tree Objects & Binary Compression

Currently advancing the C++ core: introducing SHA-256 content addressing, packfile compression, and tree object serialization under team lead architectural supervision.

Phase 3 - UPCOMING Phase

Branching, DAG Histories & 3-Way Merge

Expanding the Singly Linked List into a Directed Acyclic Graph (DAG) supporting multi-branch creation, branch switching, and ancestor-based merge resolution.

System Boundaries

Scope & Assumptions

Focusing strictly on core concepts guarantees stability, transparency, and educational clarity.

Supported In-Scope Features

  • Single user on a local filesystem (Windows x86/x64)
  • Dual Trie prefix & suffix matching for .minigitignore
  • Tracking text-based files (.cpp, .h, .txt, .md)
  • Linear commit history backed by Singly Linked List
  • Local .minigit/ directory metadata storage
  • Non-destructive checkout with stack rollback

Out-of-Scope (Full Git Features)

  • Remote server synchronization (push / pull / remotes)
  • Multi-user collaboration & authentication
  • Automated 3-way merge & conflict resolution
  • Binary delta-compression storage
